# bmo-review

git チェックアウトを対象にコードレビューを行う、独自の API を持つ単一のサービスです。設定で指定したチェックアウトを
それぞれ特定のリビジョンで読み取り(ツリー、ファイル、コミットと各コミットの diff、内容検索と定義検索)、リビジョンに
対するレビューと、その行・ファイル・フォルダへのコメントを扱い、レビューからジョブサービスへ項目を登録します。
チェックアウトには何も書き込みません。ジョブサービスには、`docs/api.md` に挙げたとおり、先方が公開しているクライアント
を通してのみアクセスします。

このサービスは独自のクライアント(`bmo_review::client`)、OpenAPI ドキュメント(`docs/openapi.json`、
`bmo-review openapi` で出力)、そしてハーネスプラグインを公開します。ハーネスプラグインは MCP サーバー
`bmo-review mcp` と、`plugin/skills/` 配下の `bmo-review` スキルから成ります。

## テスト

個人データのルール(`PERSONAL-DATA.md`)はテストベッドの `personal-data` チェックが守ります。リポジトリには次の
テストがあります。`tests/import.rs` のインポートテスト、`tests/screen.rs` のコンソールフェイスのテスト、そして
`tests/choices.rs` の画面の選択チェックです。コンソールフェイスのテストは、サービスが配信するマニフェストを、
クライアントが vendor に置いた bmo-ui リリースの読み方そのままに bmo-chat の `bmo-console-face`(マシン上の Bun)で
読み、サービスの各ルートがどの資格情報を受け付けるかを確かめます。画面の選択チェックは、画面がリストから選ばせる
すべての値が bmo-ui の単一の select に収まっていることを確かめます。コンソールバンドルにはブラウザテスト
`client/tests/browser/composer-frame.test.ts` が一つあります。このテストはサービスのスタンドイン上で開発ホスト
`client/dev-app/` から画面を開き、両方のカラースキームで次の点をページから直接読み取って確認します。コメントを
書く入力欄が、幅 1280 のコードの間でも、幅 360 と 1280 のモーダル内でも枠を一つだけ持つこと、モーダルが書きかけの
文章を破棄する前に確認し、何もなければすぐに閉じること、キーボードを出したスマートフォンほど低い画面でもモーダルの
フッターが画面内に残ること(`docs/screen.md`、「Reviewing」)。テストベッドはクライアントのマニフェストの宣言に
従ってこれをブラウザレーンで実行し、バンドルの型チェックは `client/tests/tsconfig.json` を通してその型を読みます。
その他の振る舞いテストは後回しにしています。最小限のサービス群が新しいリポジトリで立ち上がった時点でここに書いて
実行するもので、旧来の振る舞いが満たすべきだった内容は `docs/inventory.md` にまとめてあります。それまでのビルド
チェックは `cargo check --all-targets` とバンドルの型チェックです。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | サービス、クライアント、OpenAPI ドキュメント、MCP サーバー。一つのクレートを複数のモジュールに分けたもの |
| `migrations/` | ストア。これらの SQL 文を順に実行してテーブルを作る |
| `plugin/` | ハーネスプラグインのスキル `bmo-review` |
| `client/` | コンソールバンドル。コードレビュー画面、英語・韓国語・日本語・簡体字中国語の独自言語パック、`bundle/` 配下のビルド、`dev-app/` 配下の開発ホスト、ブラウザテストを持つ独立したプロジェクト |
| `deploy/` | サービスのユーザーユニット |
| `docs/` | サービスの動作を定める正典ドキュメントと OpenAPI ドキュメント |
| `tests/` | インポートテスト、コンソールフェイスのテスト、画面の選択チェック |

ルートには Cargo マニフェスト、`LICENSE`、`testbed.toml`、`install.toml`、`rustfmt.toml`、`CLAUDE.md`、
`PERSONAL-DATA.md`、`korean-ledger.json`、`settings.toml`、そしてデプロイ時に与えるローカル設定の例である
`settings.local.toml.example` があります。

## コンソールバンドル

`client/` は、コードレビュー画面を bmo-ui のコンソールプラグイン規約(bmo-ui `docs/console-bundles.md`)に沿った
コンソールバンドルとして収めています。bmo-chat の `shared-versions.toml` が固定する bmo-ui リリースの上に作られ、
そのファイルはリリースコマンドが書き出したまま `client/vendor/` に置かれています。`bun run bundle` は bmo-ui の
バンドルビルドでこれを `client/dist/` にビルドし、デプロイはリリースが有効になる前にそれをリリース内にビルドします。
サービスは bmo-chat の `bmo-console-face` を通してバンドルを配信し(`docs/api.md`、「The console face」)、画面の
文言は `client/i18n/` 配下の独自パックにあります。同じソースは Nuxt プロジェクトとして型チェックされ、その型は
`bun run api` で OpenAPI ドキュメントから生成します。バンドルのチェックは `client/` 内で実行する
`bun install --frozen-lockfile && bun run typecheck` です。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/code-review.md` | コードレビュー: プロジェクト、読み取るリビジョン、境界と除外、検索、レビュー、コメントと登録 |
| `docs/screen.md` | コンソール画面の形 |
| `docs/api.md` | ルートとその応答・コード、イベント、他ユニットの呼び出し、クライアント、ハーネスプラグイン、コンソールフェイスと設定 |
| `docs/openapi.json` | 同じルート、ボディ、ツールを、サービスの型から生成した OpenAPI 3.1 ドキュメント |
| `docs/inventory.md` | このリポジトリが旧リポジトリから引き継いだもの、そのまとまりごとの件数と出所 |
| `PERSONAL-DATA.md` | このリポジトリに決して置いてはならないもの(人の名前、住所、パス、デバイスやネットワークの情報、ルームのメンバーや会社の情報、実際の会話の一行)と、それを守るチェック |

## バージョン

バージョンはセットのもので、ビルド時に git タグから読み取ります。クレートのマニフェストのバージョンは動かない
プレースホルダーです。バージョンはオーナーが宣言したリリースでのみ変わります(`docs/api.md`、「Versions」)。
